# 선택형 Morpho 수익 금고

기본 WLD 상속 금고와 별도 계약·설정으로 구현한다. 기존 예치금은 자동으로
이동하지 않는다. 이 문서는 로컬 구현과 메인넷 활성화를 구분한다.

## 자산과 계약

| 항목 | 조건 |
| --- | --- |
| 네트워크 | World Chain, chain ID 480 |
| 예치 자산 | WLD `0x2cFc85d8E48F8EAB294be644d9E25C3030863003` |

| 서비스 수수료 | 사용자 선택 10%, 생성 시 고정, 계약 상한 10%; 원금·관리 수수료 0% |
| 운영 권한 | 관리자·업그레이드·전략 변경·수수료 변경·사용자 승인 없는 원금 출금 없음 |

전략 주소는 [공식 Morpho 캠페인](https://campaigns.morpho.org/opportunities/13294148486514685761)의
Merkl API 식별자와 실제 World Chain RPC로 교차 확인했다. 블록 **35787339**의
`asset()`은 WLD, `MORPHO()`는 `0xE741BC7c34758b4caE05062794E8Ae24978AF432`,
기존 운용 성과 수수료는 **10%**, timelock은 **3일**이었다. 기존 운용 수수료와
위험 설정은 운용자의 권한에 따라 달라질 수 있으며, 생성 화면에서 현재 수수료를 읽는다.
우리 수수료는 기존 운용 비용을 뺀 지분 가치의 증가에 적용한다.

이 통합은 검증한 V1 금고를 대상으로 한다. Morpho V2의 Fee Wrapper를 임의로
붙이지 않으며, V2는 `maxWithdraw/maxRedeem` 의미가 다르므로 주소만 바꿔 연결하면 안 된다.

## 수수료와 손실 회복

팩토리를 통한 예치는 받은 지분 수량과 실제 납입 WLD를 기록한다. 남은 지분의
원금 기준은 손실이 나도 유지된다. 추가 예치는 납입액만큼 기준을 늘리고, 부분 출금은
처분한 지분 비율만큼 기준을 줄인다. 납입 원금과 손실 회복분에는 수수료를 부과하지 않는다.
손실로 처분한 부분은 `realizedLoss`에 남아 이후 이익과 보상에서 먼저 회복된다.
이미 지급한 수수료를 나중의 손실 때문에 환불하지는 않는다.
직접 들어온 WLD나 예치 지분은 상속·회수 대상이지만 서비스 예치로 기록하지 않아
수수료를 부과하지 않는다. 잔여 승인도 예치 직후 0으로 되돌린다.

현금 출금에서는 실제 받은 WLD 중 양의 이익에 대한 수수료를 WLD로 지급한다.
지분 출금·지분 상속에서는 그 시점의 WLD 평가액으로 이익을 계산하고 수수료를
지분으로 지급한다. 지분 평가액은 현금화 보장이 아니다. 평가 호출이 실패하면
그 출금의 지분 수수료를 면제하되 조회 실패를 실현 손실로 기록하지 않는다.
기존에 확인된 실현 손실은 유지한다. 전액 현금 출금은 모든 지분을 redeem하여 반올림
잔여 지분을 남기지 않는다. 지갑에 전달된 지분을 나중에 redeem할 때 수수료를 다시 받지 않는다.

예: 원금 100 WLD가 기존 운용 비용 차감 후 110 WLD로 인출되면, 서비스 수수료
10%에서 사용자 109 WLD·운영자 1 WLD를 지급한다. 100 WLD 이하라면 수수료는 0이다.
예치금 가격 자체의 상승은 WLD 단위 이자가 아니므로 서비스 수수료에 포함하지 않는다.

[Morpho 공식 보상 설명](https://docs.morpho.org/developers/earn/concepts/rewards/)의
기본 대출이자와 별도 인센티브는 구분한다. 인센티브는 예치 지분 가격에 자동으로
들어가지 않으므로 별도 증명과 수령 거래가 필요하다. 총 APR만 표시하고 기본 이자에만
수수료를 받으면 사업 수익을 제대로 계산할 수 없다.

## WLD 보상 수령과 재예치

`claimRewardsFor(vault, cumulativeAmount, proof, minShares)`는
[공식 수령 경로](https://docs.morpho.org/developers/rewards/tutorials/claim-rewards/)의
고정 Merkl Distributor `0x3Ef3D8bA38EBe18DB133cEc108f4D14CE00Dd9Ae`를 호출한다.
수신자는 해당 금고, 토큰은 WLD로 고정한다. API가 임의 계약·토큰·수신자를 선택하지
못하며, 실제 받은 WLD 잔액 증가분을 정식 Distributor의 누적 청구액과 대조한다. 누적 금액을 그대로 전달하고,
이미 받은 누적 금액은 Distributor가 차감한다. 증명은 최대 64개로 제한한다.

상속 전에는 받은 WLD를 재예치하되 원금 기준을 늘리지 않는다. 보상과 기본 이자로
발생한 순이익은 출금·지분 이동·상속 시 같은 10% 성과 수수료를 적용한다. 보상을
클레임하는 것만으로 수수료를 먼저 수취하지 않는다. 재예치 실패나 최소 지분 미달이면
클레임까지 원자적으로 취소된다. 직접 보내준 WLD와 보상 잔액을 혼동하지 않으며,
보상 수령으로 타이머나 이의제기 기한을 갱신하지 않는다.

승인된 외부 Merkl 운영자가 앱을 거치지 않고 보상을 청구한 경우에도 Distributor의
`claimed(vault, WLD)` 누적액으로 이미 받은 보상을 추적한다. `processRewardsFor(vault,
minShares)`로 증명이나 API 없이 재예치할 수 있다. 재예치하지 않은 보상 현금도 출금·상속
시 같은 손실 회복과 수수료 계산에 포함하며, 일반 기부금과 구분한다. 재예치가 실패해도
이미 받은 현금과 원금의 출금·지분 이동·상속 경로는 유지된다. 상속 후에는 소유자의
회수 요청에서도 미처리 보상을 고정 상속인에게 먼저 정산하고 다른 자산만 소유자에게 보낸다.

상속이 끝난 뒤 발표된 보상은 고정된 `inheritanceRecipient`에게 수수료 차감 후 WLD로
직접 지급한다. 닫힌 손실의 회복분은 먼저 공제해 수수료를 면제한다. 누구나 유효한
증명을 전달할 수 있지만 자신의 지갑으로 지급처를 바꾸지는 못한다.

팩토리의 `knownVaults`는 실제 생성한 금고를 영구히 인증한다. 빈 금고의 현재 슬롯을
해제해도 늦은 보상·상속 경로가 사라지지 않는다. 상속 전 빈 금고를 해제한 뒤 보상이
들어오면 원래 금고의 지정 상속인이 신청하고 7일 후 지급받을 수 있으며, 새 금고는
영향을 받지 않는다. 원래 소유자 권한도 계약에 남는다. `recoverArchivedVault(vault)`는
영구 생성 기록과 원래 소유자를 확인하고, 상속 전에는 갱신하여 신청을 취소한 뒤 남은
WLD와 수수료 차감 지분을 그 소유자에게 보낸다. 현금 유동성이 없어도 작동하며 새
현재 금고에는 영향을 주지 않는다. 상속 취소 후 해제한 빈 금고의 늦은 보상도 이 경로로
회수한다. 상속 후에는 직접 들어온 다른 자산만 회수하고 캠페인 보상은 고정 상속인에게
계속 지급한다. 해제한 금고에서는 현재 금고를 대상으로 하는 소유자 버튼을 제공하지
않는다. 이전 금고 링크를 보관해야 한다. 기본 금고의 현재 슬롯 인증 규칙은 유지한다.

화면은 수령 가능한 WLD, 아직 root에 발표되지 않은 대기 보상, 외부 청구로 이미 받은
미처리 WLD를 구분한다. 이미 받은 보상의 처리 버튼은 보상 API 장애와 무관하게 제공한다.
수령 전에 최신 API를 다시 검증하며, 보상 조회 실패가 원금 출금이나 상속을 막지 않는다.
현재 클레임은 사용자의 World App 거래로 수행한다. 자동 상속 실행자는 API 보상 수령을
선행 조건으로 삼지 않는다. 실제 새 금고의 인센티브 적립을 관측한 것은 아니므로,
통합 테스트 성공을 캠페인 수익 확정으로 취급해서는 안 된다.

### 현재 WLD 금고의 사업성

2026-10-02의 Feather 인계 공지 정정과 WLD·USDC 대안 비교는
[예치 경로 판단](MORPHO_ROUTE_DECISION.md)에 기록했다. 화면 운영 변경을
외부 금고의 운용자 변경으로 혼동하지 않는다. 현재 앱은 일반 보상과 기본 이자를
분리해 표시하며, 인증 우대나 고정 수익을 포함하지 않는다.

블록 **35788754**(2026-10-02 03:52:27 UTC)에 실제 배분과 IRM을 조회했다.
약 2574.65만 WLD 중 2573.38만 WLD, 즉 **99.95%**가 IRM이 없고 차입이 없는
대기 시장에 있었다. 나머지 두 대출 시장의 이자율을 배분 비중으로 가중하고
기존 운용 수수료 10%를 적용한 기본 대출 수익률은 연환산 **약 0.00133%**다.
인센티브를 제외한 근사치이며, 저장된 시장 상태와 IRM의 최근 갱신 구간을 사용한다.
실제 자산 배분·차입률·금리·손실·운용 수수료가 변하므로 미래 수익을 뜻하지 않는다.

이 상태가 유지되고 이익을 전부 실현한다고 가정해도, 우리 금고 TVL **100만 WLD**에서
10% 성과 수수료는 **연 약 1.33 WLD**다. 출금이 없다면 실제 수수료 수취도 없다.
이 수치는 **기본 대출이자만의 매출**이다. 전체 WLD 보상을 빠뜨린 상태로 사업성
전체를 부정해서는 안 된다. 2026-10-02 04:21:44 UTC의 공식 Merkl API에는 기본 이자
약 0.0013%, 일반 WLD 보상 약 1.6995%, 인증 사용자 추가 보상 약 7.5394%가 있었고,
합계는 약 9.2402%였다. 사용자가 본 9.19%와 같은 구조이며 변동하는 시점별 수치다.

일반 캠페인은 당시 별도의 World ID hook 없이 실제 Re7 WLD 지분 보유를 대상으로 했다.
인증 추가 캠페인은 `WorldIDAddressBook` hook과 사용자당 첫 1000 WLD 한도를 요구했다.
우리 예치 지분은 소유자 지갑이 아니라 개인 금고 계약이 보유하므로, 소유자가
인증됐다는 사실만으로 계약이 우대 보상에 참여한다고 가정할 수 없다. 앱 자체의
World ID 인증과 공식 주소 등록 증명은 동일한 조건이 아니다.

따라서 WLD를 유지하면서 **실제 적립·수령한 보상까지 10% 수수료에 포함**한다.
월드 앱과 같은 인증 우대 금리는 약속하지 않는다. 일반 보상 약 1.7%가 유지되고 실제
자격·수령·이익 실현이 충족된다는 가정에서만 TVL 100만 WLD의 수수료는 연 약
1700 WLD 규모가 된다. 캠페인이 종료되거나 자격이 충족되지 않으면 달라진다.
이 WLD 수익 분석 이후 사용자 승인에 따라 별도의 USDC 금고를 구현했다.
USDC 원금·이자와 WLD 보상의 회계 및 지급은 분리하며 WLD를 자동 환전하지 않는다.
단위·수수료·활성화 조건은 [USDC 설계](USDC_YIELD.md)를 따른다.

[보상 조회 결과](morpho-wld-rewards-2026-10-02.json)와
[World Earn 공식 안내](https://support.world.org/hc/en-us/articles/47022343436307-How-do-I-use-Earn)를
함께 확인한다. 출시 판단은 새 금고의 실제 적립 조건과 통합 검증에 따라 해야 한다.

## 상속과 유동성

갱신 기한 만료 → 지정 상속인의 신청 → 7일 검토 → 고정 상속인에게 실행한다.
소유자는 실제 이전 전까지 갱신하여 신청을 취소할 수 있다. 현금 상속은 모든 지분
redeem을 시도한다. 실패하면 수수료 차감 후 지분과 대기 WLD를 상속인에게 넘긴다.
실행자는 수신자를 지정할 수 없다. 예치 지분은 일반 ERC-20 rescue로 빼낼 수 없다.

자동 redeem에는 350000 gas, 지분 평가에는 150000 gas를 허용하여 외부 호출이
실행을 고갈시키지 못하게 한다. 네트워크 실행 제약 때문에 현금 유동성이 있어도
지분 지급으로 끝날 수 있다. 소유자는 활성 상태에서 지분을 지갑으로 이동할 수 있고,
소유자·상속인은 지갑 지분을 현재 유동성만큼 인출할 수 있다. 지갑 전액 인출은
전체 previewRedeem 값과 maxWithdraw를 비교해 maxRedeem 반올림 잔여 지분을 피한다.

원금 손실, 부실채권, 오라클, 운용자, 계약, WLD 가격과 인출 지연 위험이 있다.
[Morpho 위험 안내](https://docs.morpho.org/learn/resources/risks/)를 사용자 선택 전에
고지한다. 이 새 통합은 독립된 제3자 보안 감사를 받지 않았다. 코드 검토와 포크 테스트는
그 감사나 실제 휴대전화 World App 승인을 대신하지 않는다.

## 검증과 활성화

로컬 단위 테스트는 수수료·손실 회복·부분 출금·슬리피지 원자성·권한·이의제기·
보호 지분·재진입·외부 gas 고갈을 검증한다. Anvil/D1 테스트는 현금과 지분 지급,
여러 팩토리의 공유 예산·중단 복구·50 RPC 제한을 확인한다. 브라우저는 기존 금고와
선택형 생성, 동의, 실제 출금·지분 상속·후속 redeem, 모바일 폭을 검증한다.
World Chain 블록 35787339 포크에서는 실제 예치·현금 상속·지분 이동·후속 redeem을
검증하며, 실패 분기는 모의 redeem 거절임을 테스트 이름에 명시한다. 보상 포크 테스트는
정식 Distributor·WLD·Morpho 코드를 실행하되 root만 로컬로 주입한다. 공식 캠페인의
적립 자격이나 실제 배포 금고의 보상 수익을 증명하는 테스트는 아니다. 실자금이나 서명은 사용하지 않는다.

메인넷 활성화 전에는 다음 결과가 확정되어야 한다.

1. 성과 수수료율과 운영자 수취 주소, 새 계약 배포의 범위를 확정한다. 계약은 이를 나중에 바꾸지 못한다.
2. 최신 전체 검증과 정확한 커밋 SHA의 독립 코드 리뷰를 완료한다.
3. `node scripts/deploy-yield-factory.mjs`로 먼저 dry-run한다. 기존 운영자 지갑을 배포자·수수료 수취인으로 사용하고, 가스 한도 650만 및 실행·L1 합계 0.000015 ETH 상한을 검증한다. `--broadcast`를 명시한 경우에만 전송하며, 응답 중단 후 재실행은 `.env.yield-deployment.json`의 동일 서명 거래를 복구한다. 팩토리 생성자는 동일한 고정 설정의 immutable 배포 helper를 함께 생성한다. helper는 팩토리만 금고를 생성하도록 허용하며 관리자 권한이 없다. 두 runtime·설정 getter·Sourcify 소스 일치를 확인한다. Foundry 대안은 `script/DeployMorphoFactory.s.sol`이다.
4. 기존 World App 허용 목록을 보존하면서 새 팩토리와 Re7 WLD 지분 토큰을 추가한다. 기존 기본 팩토리와 WLD 주소를 덮어쓰지 않는다.
5. 저장소의 `VITE_YIELD_FACTORY_ADDRESS`, `VITE_YIELD_FACTORY_DEPLOY_BLOCK`, `VITE_MORPHO_VAULT_ADDRESS`를 함께 설정한다. 배포 workflow가 프론트와 Worker의 대응 변수를 함께 주입하며, yield가 설정되면 Worker의 최대 거래 가스를 850000으로 지정한다. 직접 배포하는 경우 Worker에도 `YIELD_FACTORY_ADDRESS`, `MORPHO_VAULT_ADDRESS`와 가스 설정을 명시한다.
6. 수익형 실행에 `FINALIZER_MAX_GAS=850000`을 사용한다. 기존 하루 ETH 한도와 OP 예비금은 유지한다. 새 가스 충전이나 하루 한도 증액은 별도 비용 결정이다.
7. Pages·Worker 배포 후 새 팩토리 지원 상태, 전진하는 cron 기록, 실제 앱 설정과 지갑 승인·예치·출금 경로를 확인한다. 요금 안내·약관·이미지·스토어 설명을 일치시키고 변경 심사를 신청한다.

주소가 비어 있으면 기본 서비스에는 수익 기능이 나타나지 않는다. D1의 기존 스키마와
서명 키를 재사용하며, 운영 signer는 이 실행 때문에 사용자 금고 출금 권한을 얻지 않는다.
